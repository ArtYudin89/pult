# Пульт — инструкция для ИИ

Для агента, который ведёт дела в Пульте: Claude Code, Codex, Cursor и любого другого, кто умеет запускать
команды. Человеку отсюда нужен только первый раздел — блок для инструкций агента.

## Блок для инструкций агента

Вставьте его в файл, который агент читает в начале каждой сессии: `CLAUDE.md` у Claude Code, `AGENTS.md`
у Codex, правила у Cursor. Путь к `pult.py` поправьте на свой.

```markdown
## Пульт — статусы задач
Статусы моих задач живут в Пульте, а не в памяти, заметках или HANDOFF-файлах.
Клиент: `python -X utf8 /путь/к/pult/pult.py` (дальше — pult.py); как работать — docs/for-ai.md рядом с ним.
- Начало сессии: `pult.py brief` — что горит; по проекту — `pult.py brief --project <id>` (id — `pult.py projects`);
  карточка целиком — `pult.py show КЛЮЧ`.
- Конец сессии — двигать карточки самому, без просьбы, одним пакетом `pult.py apply файл.json`: что сделано
  (done с итогом), что дальше (next), чего ждём и когда проверить (wait + check), новые задачи (add).
  Пакет — файлом, не текстом в командной строке.
- «КОНФЛИКТ» в выводе: карточку после тебя менял другой — `pult.py show КЛЮЧ`, учесть чужую правку, повторить.
- Ключи и ссылки входа из папки `.local/` рядом с pult.py не выводить в чат, логи и коммиты.
```

## Начало сессии

```
pult.py brief                   # просрочено, пора проверить, в работе, ждёт, следующие, входящие
pult.py brief --project site    # всё по одному проекту
pult.py show W-12               # карточка: описание, шаги, вложения, журнал
pult.py log --since 2d          # что за два дня поменяли другие: люди, другие агенты и сессии
```

Сводка — первое, что делает сессия: по ней `pult.py` запоминает, какими вы видели карточки (см.
«Одновременная правка»).

## Конец сессии: пакет изменений

Один файл в конце каждой сессии, без отдельной просьбы человека:

```json
[
  {"op": "done", "key": "W-12", "result": "итог одной строкой"},
  {"op": "set", "key": "W-13", "status": "wait", "wait": "ответ клиента", "check": "+2",
   "comment": "письмо отправлено"},
  {"op": "set", "key": "W-14", "next": "следующий шаг", "holder": "me"},
  {"op": "note", "key": "W-14", "text": "что сделано или решено — запись в журнал"},
  {"op": "step", "key": "W-14", "check": 2},
  {"op": "step", "key": "W-14", "add": "новый шаг"},
  {"op": "add", "project": "site", "title": "Новая задача", "status": "next", "holder": "me",
   "next": "первый шаг", "checklist": ["шаг 1", "шаг 2"]},
  {"op": "attach", "key": "W-12", "file": "report.md", "comment": "отчёт о проверке"}
]
```

```
pult.py apply ops.json
```

Каждая строка вывода — итог одной операции; ошибка в одной не останавливает остальные, в конце —
«выполнено N из M».

### Что писать в карточку

- **next** (следующий шаг) — одно действие, с которого начнёт следующая сессия, а не весь план.
- **wait + check** — чего ждём и когда проверить. Ожидание без даты теряется, с датой само всплывёт в
  сводке как «пора проверить».
- **due** — настоящий срок (оплата, дедлайн), а не «хорошо бы к пятнице».
- **result** у `done` — итог одной строкой: что получилось, а не что делали.
- **comment** и **note** — журнал: решения, найденные причины, ссылки. Описание (`notes`) — суть задачи,
  а не дневник.
- **holder** — кто держит: `me`, id участника или `-` (никто). Задачу, которую ждём от человека, держит он.

### Поля и форматы

- `status`: `inbox` (входящие), `next` (следующие), `doing` (в работе), `wait` (ждёт), `done` (готово),
  `dropped` (снято); можно и по-русски.
- Даты: `27.10`, `27.10.2026`, `2026-10-27`, `+3` (через три дня), `+2w`, `сегодня`, `завтра`; `-` — убрать.
- Текстовое поле `"-"` — очистить. `set` меняет только названные поля.
- `done` с `"dropped": true` — снято, а не сделано. Удалить задачу (`delete`) может только владелец Пульта.
- Разделы и проекты заводит владелец: `{"op": "area", "id": "work", "name": "Работа", "prefix": "W"}`,
  `{"op": "project", "id": "site", "area": "work", "name": "Сайт", "note": "подпись"}`. Повтор с тем же
  `id` — правка. Закрытый раздел или проект (`"closed": true`) видят только те, кому открыли его отдельно.

## Одновременная правка

С Пультом работают сразу несколько агентов и людей. `pult.py` помнит, какими эта сессия видела карточки
(папка `.local/seen/`), и отправляет правку с этой версией. Если с тех пор кто-то поменял те же поля,
сервер его правку не затрёт, а `pult.py` напишет «КОНФЛИКТ» и покажет, кто и что поменял. Тогда
`pult.py show КЛЮЧ`, учесть чужое и повторить. Правки разных полей сливаются сами.

Сессию различает метка: в Claude Code — начало `CLAUDE_CODE_SESSION_ID`, у других агентов — переменная
`PULT_SESSION` (латиница, цифры и `._:-`, до 40 знаков). Без метки `pult.py` не помнит версий карточек:
правка уходит без сверки и может перезаписать чужую правку тех же полей, а в журнале не различить сессии
одного агента. Задайте метку в начале сессии, например `PULT_SESSION=codex-2610a`.

## Чего не делать

- Не держать статусы в своей памяти и заметках: память — для знаний и уроков, Пульт — для статусов.
  Два места со статусами быстро расходятся.
- Не печатать ключи и ссылки входа. `invite` и `key` кладут их в файлы и печатают только путь — так и
  передавайте человеку: путь, а не содержимое.
- Не передавать кириллицу и длинный текст аргументами командной строки — только файлом через `apply`:
  в оболочках Windows кавычки и кодировка ломаются.

## Другие команды

```
pult.py ls --project site --status wait          # список задач
pult.py find капча                               # поиск, как на странице
pult.py digest                                   # утренняя сводка, как она придёт в Telegram
pult.py attach W-12 report.md -m "что приложил"  # вложение; fetch НОМЕР — скачать, detach НОМЕР — удалить
pult.py url W-12                                 # адрес карточки на странице
pult.py people                                   # участники, доступ, входы и ключи
pult.py person masha --name Маша                 # новый человек (это может владелец)
pult.py grant masha site edit                    # доступ: all | area:ID | проект; view | edit | -
pult.py invite masha --days 7                    # ссылка для входа человеку → файл в .local/
pult.py person codex --name Codex --kind model --owner anya   # модель человека anya
pult.py key codex --label codex-laptop           # ключ модели → файл в .local/
```

Все команды — `pult.py --help`. HTTP API для агентов без `pult.py` — `/static/api.txt` на самом Пульте.

## Установка по просьбе человека

Если человек просит поставить Пульт на его компьютер и подключить вас:

1. Проверьте Python: `python --version` (нужен 3.9 или новее; на Linux и macOS — `python3`).
2. `git clone https://github.com/ArtYudin89/pult` туда, куда скажет человек.
3. Спросите, как показывать его имя на странице, и создайте Пульт, назвав себя:
   `python server/pult_server.py init --db .local/pult.db --name "Имя" --ai "Claude"` (или `Codex` — как вас зовут).
4. Запустите сервер фоном: `python server/pult_server.py serve --plain-http --db .local/pult.db --backup-dir .local/backup`.
   Автозапуск — [install.md](install.md#автозапуск).
5. Проверьте: `python pult.py whoami` и `python pult.py brief` — в сводке карточка «Подключить ИИ к Пульту».
6. Назовите человеку **путь** к ссылке для первого входа: `.local/login-<id>.txt` (на Windows рядом лежит
   `.url` — открывается двойным щелчком). Саму ссылку не печатайте.
7. С согласия человека добавьте блок из начала этого файла в свои инструкции.
8. Когда всё работает, закройте карточку «Подключить ИИ к Пульту» пакетом `apply` и предложите завести
   его проекты.

Пульт на сервере ставит человек — нужны права root, см. [install.md](install.md#на-сервере). Вам он
передаст адрес и файл с ключом: `python pult.py connect https://сервер:9447 --token-file путь/к/ключу`.
