Пульт — описание API для моделей

Адрес — тот же, где открыта страница Пульта (https://…:9447). Ключ выдаёт хозяин модели на странице:
Участники → модель → «Выдать ключ». Ключ передаётся в каждом запросе заголовком
    Authorization: Bearer <ключ>
Модель видит и правит не больше, чем её хозяин. Тела запросов и ответов — JSON в UTF-8
(Content-Type: application/json).

Готовый клиент командной строки — pult.py (Python 3.9+, без зависимостей) и инструкция для ИИ:
https://github.com/ArtYudin89/pult — pult.py, docs/for-ai.md.

Чтение
  GET   /api/me                      кто я: id, имя, роль
  GET   /api/state                   проекты, участники и задачи (без описаний); access — мой доступ
                                     к проектам: view (читаю) или edit (правлю); writers у проекта —
                                     кто может его править и держать его задачи; files у задачи —
                                     число вложений; limits.file — предел одного вложения в байтах
  GET   /api/task/<номер>            карточка: описание, шаги, журнал, files — список вложений
                                     [{id, name, size, image, created_at, created_by}, …]
  GET   /api/journal?since=2026-10-26T00:00:00%2B03:00&limit=100&project=<id>&task=<номер>
  GET   /api/digest                  утренняя сводка по моим проектам: {text, html, counts}
  GET   /api/file/<id>[?dl=1]        вложение; картинки отдаются для показа, остальное и ?dl=1 —
                                     на скачивание (Content-Disposition: attachment)

Запись (нужен доступ edit к проекту задачи)
  POST  /api/task                    {project, title, status?, holder?, next?, wait?, check?, due?,
                                      notes?, checklist?, comment?}
  PATCH /api/task/<номер>            {поля…, version, comment?} — меняются только названные поля
  POST  /api/task/<номер>/comment    {text} — запись в журнал
  POST  /api/task/<номер>/files      вложение: тело запроса — сам файл (любой Content-Type), имя — в
                                     заголовке X-File-Name в %-кодировке UTF-8; до 25 МБ; ответ 201
                                     {file, task}
  DELETE /api/file/<id>              удалить вложение

Разделы и проекты (только владелец Пульта)
  POST  /api/area                    {id, name, prefix, closed?, sort?} — prefix: заглавная латиница и
                                     цифры, до 6 знаков; номера задач раздела — PREFIX-1, PREFIX-2, …
  PATCH /api/area/<id>               {поля…}; префикс раздела, где уже есть задачи, не меняется
  POST  /api/project                 {id, area, name, note?, closed?, sort?}
  PATCH /api/project/<id>            {поля…}
  closed — закрытый раздел или проект: доступ «ко всем проектам» и к разделу его не открывает.

Поля: status — inbox, next, doing, wait, done, dropped; даты (check, due) — ГГГГ-ММ-ДД или null;
holder — id участника или null; checklist — [{"t": "шаг", "on": false}, …] целиком.
Удалять задачи может только владелец Пульта — закрывайте статусом dropped.

Одновременная правка
  Передавайте в PATCH номер версии карточки (version), какой вы её видели. Если с тех пор другие
  поменяли те же поля, ответ 409: в нём текущая карточка (task) и изменения с вашей версии
  (conflicts). Перечитайте карточку и решите заново. Правки других полей сливаются сами.
  Заголовок X-Pult-Session: <метка сеанса> (латиница, цифры, . _ : -, до 40 знаков) различает
  ваши сеансы в журнале, и ваши же правки того же сеанса при сверке версий чужими не считаются.

  Вложение тоже даёт карточке новую версию, но задевает только сами вложения: правке полей оно
  не мешает, а удаление задачи по версии до вложения получит 409.

Ответы с ошибкой — {"error": "…"}: 400 неверные данные, 401 ключ не подходит, 403 нет права,
404 нет такой задачи или к ней нет доступа, 409 конфликт версий, 413 файл больше предела,
429 много неудачных входов (пауза 10 минут), 507 место для вложений кончилось.
